# LongLoop

Run this project (the MoA pipeline) on your own project — **unattended, iterating for up to 24 hours**: no forgetting, no stopping, no repeating. The **concierge (门童) is the core**: each round the loop wakes the concierge, which routes execution through the pipeline by confidence — the exact same 22 agents you use in daily conversation.

## 1. Mechanism

```
longloop/long-loop.ps1 (driver script, loop orchestration)
        │  injects the [长程自完善模式] scheduling protocol each round
        ▼
     门童 concierge (primary router)
        │  task(@工具人) evidence → confidence-based pipeline dispatch
        ▼
   swift / mid chain / flagship chain / frontend chain (execute, write back state)
        ▼
   .moa/longloop/state.json ← single source of truth (maintained by agents)
   .moa/longloop/足迹.md     ← append-only history (anti-forgetting; structured entries: did / verify / evidence / negative result / next step)
```

- **Fresh session every round**: `opencode run` opens a new session each round — context never bloats; memory lives in state files, not chat logs
- **Native concierge routing**: no new agents introduced — simple tasks go to swift/mid chain, exploratory tasks fan out to the opinion layer, heavy tasks use the flagship chain, low confidence routes through @置信度评估
- **Anti-forgetting**: each round starts with evidence gathering (@工具人 reads state.json + 足迹.md); done tasks are never redone, blocked routes are never retried (unless evidence changed); half-done tasks record "where I am / what's next" in the roadmap note
- **Anti-stalling**: blocked tasks (human decision / external credentials / destructive ops) go to `blockers` and the loop switches tasks; while waiting for the user the interval stretches to 30 min and resumes automatically once you edit state.json
- **True stop conditions** (all must hold): roadmap all done/blocked with no blockers → the executing agent calls `moa_finish` to set `finished=true` (the script refuses rounds after that); or the script's safety net — 4 consecutive rounds with no state change (state.json **and** 足迹.md hash both unchanged); or -MaxIterations / -MaxHours reached

## 2. Quick start

Prerequisite: the `opencode` CLI must be available (`npm install -g opencode-ai`, or `curl -fsSL https://opencode.ai/install | bash` on macOS/Linux). **The loop drives each round via `opencode run` — it cannot run without the CLI**; the desktop app only serves as a viewer (see below) and cannot replace it. The CLI shares config and login with the desktop app.

```powershell
# First launch (creates .moa/longloop/state.json with your goal)
pwsh longloop/long-loop.ps1 -Goal "Raise test coverage from 60% to 85%, module by module" -Dir . -IntervalSec 180 -MaxHours 200

# Dry run (show config + first-round prompt, no execution)
pwsh longloop/long-loop.ps1 -Goal "..." -DryRun

# Single round (smoke test / debug)
pwsh longloop/long-loop.ps1 -Goal "..." -RunOnce

# Resume after a break: just restart (no -Goal; reads existing state.json)
pwsh longloop/long-loop.ps1
```

Linux/macOS work the same (needs `pwsh`). If opencode is not on PATH, set the `OPENCODE_BIN` environment variable to the executable.

### Desktop app mode (watch it run)

Beyond the CLI, the loop can drive a **standalone `opencode serve` instance**, and the desktop app (OpenCode App) can attach to the same instance via Add server to watch every iteration's sessions and messages live.

```powershell
# 1. Start the server (on 4096; credentials are yours to pick; -SpawnServer lets the script start it for you; if the port is taken, -SpawnServer falls back to the next free port and prints the actual one)
opencode serve --port 4096 --hostname 127.0.0.1
#    (On Windows, set env vars first: OPENCODE_SERVER_USERNAME=opencode, OPENCODE_SERVER_PASSWORD=your-password)

# 2. Drive the loop against the external server
pwsh longloop/long-loop.ps1 -Goal "..." -ServerPort 4096 -ServerPassword "your-password" -RunOnce
#    Or add -SpawnServer -ServerPassword "your-password" to have the script start the server itself
```

- Desktop: Settings → Servers → Add server, fill `http://127.0.0.1:4096` / `opencode` / your password; to connect automatically on every app launch (instead of starting a local server), set it as default in the Add server panel and restart the app
- Each round is a fresh `opencode run` session; the title is auto-generated by opencode (no `--title` passed — its title agent summarizes the first line, e.g. "执行 t2：改写 round2") — on the server you can see the full message stream: concierge evidence gathering, dispatch, and the executing agent
- State is maintained through the **moa-loop MCP control plane** (below): executing agents call `moa_*` tools instead of editing state.json/足迹.md directly
- **Known limitation (upstream bug, be aware)**: new loop sessions do **not** appear in the desktop session list automatically — click "Load more" to refresh. This is a known upstream opencode issue ([sst/opencode#31073](https://github.com/sst/opencode/issues/31073) — session updates driven by external processes are not pushed to other clients' views; not yet fixed upstream). The loop never depends on this mechanism and keeps running; feel free to delete finished sessions in the desktop app to keep the list manageable

### moa-loop MCP control plane (how agents maintain state)

`opencode.json` registers `mcp.moa-loop` (`node longloop/server.js`, zero-dependency), exposing 8 tools: `moa_state_read` / `moa_roadmap_add` / `moa_roadmap_update` / `moa_blockers_add` (with `attempted` diagnosis + `resume` condition fields) / `moa_blockers_resolve` / `moa_footprint_append` (with optional `evidence` ref: commit:/smoke:/pr:/run:) / `moa_heartbeat` / `moa_finish` (guarded finalization: only sets `finished=true` when all tasks are done/blocked and no blockers remain). Any agent with tool permissions can call them in-session (no CLI/desktop distinction).

Unattended-reliability grants (already in `opencode.json` → `permission`):

- `moa-loop_*: allow` — state-machine tools never prompt for confirmation
- `grep` / `glob` / `list: allow` — read-only tools allowed so headless rounds never hang on a permission prompt
- Each round's protocol tells executing agents: "only `moa_*` and `read`; if you want to go further, write it into the note and hand it back" — a bounded segment that prevents exploratory dead-ends from stalling a round

## 2.1 Task-sheet structure (todowrite)

Each round the executing agent plans its own work as a task sheet — the loop does **not** invent a new system, it uses opencode's native `todowrite` (the same checklist you see in interactive sessions). This is how the leader's task-sheet discipline (adapted from the khazix leader skill) is carried into unattended rounds:

- **Task list = todowrite**, not prose**: open the round by breaking the assigned task into steps with `todowrite`, then tick each one off as it completes
- **Acceptance = a command with a machine-readable verdict**, not a description (e.g. `node --check` passes, a smoke script exits 0, a grep returns the expected count). A step is done only when its command says so
- **Reverse verification (验真试验 / mutation test)**: for every check whose failure "nobody would notice", deliberately break the implementation once and re-run it — the check must go red; restore, and it must go green. A check that cannot fail is a fake acceptance. Paste both outputs into the 验证 (verification) section of 足迹.md
- **Anti-cheating rules (红线·防作弊)**: skipping, marking TODO as done, relaxing assertions, mocking, deleting tests, `|| true`, or tweaking thresholds all count as failure; test counts may only stay ≥ baseline
- **3 strikes → switch**: the same acceptance criterion failing 3 times in a row → mark the task blocked and move on ("didn't make it but said so clearly" passes; "made it worse" fails)
- **Resume section (断点恢复)**: every session starts by reading state.json + 足迹.md and restating "where we are" before touching anything — never continue from memory

The templates under `.moa/` already carry these: 界线.json (frozen acceptance + 红线·防作弊 + mutationTest) and 足迹模板.md (with the 断点恢复 section).

## 3. State protocol (.moa/longloop/state.json)

```json
{
  "goal": "the long-running goal",
  "phase": "working | waiting_user | finished",
  "roadmap": [{ "id": "t1", "title": "...", "status": "open|in_progress|done|blocked", "note": "resume point" }],
  "blockers": [{ "question": "question needing a human decision", "context": "...", "since": "ISO time" }],
  "finished": false
}
```

- `phase=waiting_user`: all tasks blocked — edit state.json to answer the blockers (turn the question into an answer, or delete it and reopen the task); the loop resumes next round
- Machine fields (iteration/updated_at/last_round_change) are maintained by the script, not the agents
- 足迹.md template: `.moa/longloop/足迹模板.md`; the 「弃选」 (discarded) section records abandoned routes to avoid retrying them later

## 4. Cadence and cost (economy mode by default)

- Default 180-second interval; one bounded task per round (flash-class mostly) — roughly 200-400 rounds/day
- The unattended constraint is baked into every round's protocol: unclear requirements do **not** burn the flagship chain — they go to blockers for the user
- Track spending: `opencode stats`

## 5. FAQ

| Symptom | What to do |
|---------|------------|
| Auto-stopped after 4 rounds with no state change | Check loop.log and 足迹.md — usually all tasks blocked or agent stuck; restart after a manual look (resume-safe) |
| Interval too fast/slow | Tune -IntervalSec; waiting_user automatically uses 1800s |
| state.json edited externally | The script re-reads it every round and picks it up immediately — that is the "user reply" channel |
| Change the goal | Stop the loop, edit state.json's goal + reset roadmap (or delete state.json and start again with -Goal) |
| Machine reboot | Just restart the script; state.json is on disk, iterations restart from 1 but progress is not lost |
| New sessions not visible in desktop | Upstream bug (#31073), known limitation: click "Load more" to refresh the list; the loop itself is unaffected |
| Two loops running at once | Not supported: one state.json may only be driven by one loop (they would trample each other's state). Stop the second one, or give it its own directory (-Dir) |
| `opencode run` reports Access is denied on Windows | opencode.exe was quarantined/blocked by Defender (binary flagged but PE intact). Fix: reinstall with `npm install -g opencode-ai` to overwrite, or add the npm global directory to Defender exclusions |
