# 长程自完善（Long-Running Self-Improvement）

让本项目（MoA 流水线）在你的项目上**无人值守、24 小时不间断迭代**：不遗忘、不停止、不重复。以**门童为核心**——循环每轮唤醒门童，由它按置信度路由流水线执行，任务流经与你日常使用完全相同的 22 个 agent。

## 一、机制

```
longloop/long-loop.ps1（驱动脚本，循环编排）
        │ 每轮注入 [长程自完善模式] 调度协议
        ▼
     门童（primary 路由）
        │ task(@工具人) 取证 → 按置信度派发流水线
        ▼
   闪电侠/中级链/旗舰链/前端链（执行，回写状态）
        ▼
   .moa/longloop/state.json ← 唯一事实源（agent 维护）
   .moa/longloop/足迹.md     ← 历史记录 append-only（防遗忘；结构化条目：做了什么/验证/证据/负结果/下一步）
```

- **每轮独立会话**：`opencode run` 每轮开新 session，上下文永不膨胀；记忆靠状态文件，不靠聊天记录
- **门童原生路由**：循环不引入新 agent——简单任务走闪电侠/中级链，探索型任务意见层并行，重任务走旗舰链，置信度拿不准走 @置信度评估
- **防遗忘**：每轮先取证（@工具人 读 state.json + 足迹.md），已 done 不重做、已 blocked 不重试（除非证据变化）；做到一半的任务在 roadmap note 里写「已到哪/下一步」
- **防停止**：受阻任务（要人决策/外部凭证/破坏性操作）进 blockers 挂起，换任务继续；等用户答复期间自动拉长轮间隔（30 分钟），用户改 state.json 答复后自动恢复
- **真停止条件**（全部满足才停）：roadmap 全 done/blocked 且 blockers 空 → 执行 agent 调 `moa_finish` 置 `finished=true`（校验不通过拒绝收官，防提前收尾）；或脚本侧连续 4 轮状态无变化（state.json **与** 足迹.md 双文件哈希均不变，卡死兜底）；或到达 -MaxIterations / -MaxHours

## 二、快速开始

前置：`opencode` CLI 必须可用（`npm install -g opencode-ai`，或 macOS/Linux `curl -fsSL https://opencode.ai/install | bash`）。**循环每轮用 `opencode run` 驱动会话，没有 CLI 无法运行**——桌面版只能作为观看端挂载（见下），不能替代 CLI。CLI 与桌面版共享配置与登录。

```powershell
# 首次启动（会在 .moa/longloop/ 生成 state.json，写入你的目标）
pwsh longloop/long-loop.ps1 -Goal "把项目测试覆盖率从 60% 提到 85%，逐模块渐进" -Dir . -IntervalSec 180 -MaxHours 200

# 预演（不执行，只看配置与首轮 prompt）
pwsh longloop/long-loop.ps1 -Goal "..." -DryRun

# 只跑一轮（冒烟/调试）
pwsh longloop/long-loop.ps1 -Goal "..." -RunOnce

# 断点恢复：直接重启（不带 -Goal，读取已有 state.json 继续）
pwsh longloop/long-loop.ps1
```

Linux/macOS 同理（`pwsh` 可用即可）。找不到 opencode 时设置环境变量 `OPENCODE_BIN` 指向可执行文件。

### 桌面版模式（边跑边看）

CLI 之外，循环可以挂在**独立 `opencode serve` 实例**上，桌面版（OpenCode App）同一实例挂载后即可实时查看每次迭代的会话与消息。

```powershell
# 1. 起服务（起在 4096，凭据可自定义；-SpawnServer 可让脚本自动拉起；端口被占用时 -SpawnServer 会自动顺延并提示实际端口）
opencode serve --port 4096 --hostname 127.0.0.1
#    （Windows 下建议先设环境变量：OPENCODE_SERVER_USERNAME=opencode、OPENCODE_SERVER_PASSWORD=你的密码）

# 2. 循环连外部 server 驱动
pwsh longloop/long-loop.ps1 -Goal "..." -ServerPort 4096 -ServerPassword "你的密码" -RunOnce
#    或加 -SpawnServer -ServerPassword "你的密码" 让脚本自动起服务
```

- 桌面版：Settings → Servers → Add server，填 `http://127.0.0.1:4096` / `opencode` / 密码；想每次启动自动连（不再起本地 server），在 Add server 面板勾选设为默认并重启应用
- 循环每轮是 `opencode run` 新会话，标题由 opencode 自动生成（不传 `--title`，title agent 按首句概括，如「执行 t2：改写 round2」）——服务端/桌面版可见门童取证、派发、执行 agent 的完整消息流
- 状态维护走 **moa-loop MCP 控制面**（见下），执行 agent 用 `moa_*` 工具写 state.json/足迹.md，而不是直接改文件
- **已知限制（上游 bug，请知晓）**：循环新建的会话**不会自动出现在桌面版会话列表**，需手动点「加载更多」刷新。这是 opencode 上游已知问题（[sst/opencode#31073](https://github.com/sst/opencode/issues/31073)——外部进程驱动的会话更新不会推送到其他客户端视图，官方未修复）。循环自身不依赖该机制，照常运行；可随时在桌面版删除已完成的会话，控制列表长度

### moa-loop MCP 控制面（agent 维护状态的方式）

`opencode.json` 已注册 `mcp.moa-loop`（`node longloop/server.js`，零依赖），暴露 8 个工具：`moa_state_read` / `moa_roadmap_add` / `moa_roadmap_update` / `moa_blockers_add`（含 attempted 已尝试诊断 + resume 恢复条件字段）/ `moa_blockers_resolve` / `moa_footprint_append`（可选 evidence 证据 ref：commit:/smoke:/pr:/run:）/ `moa_heartbeat` / `moa_finish`（带校验的收官：只有全 done/blocked 且 blockers 空才置 finished=true）。任何带工具权限的 agent 在会话里都能直接调用（无需 CLI/桌面版区别）。

无人值守可靠性配套（已写入 `opencode.json` 的 permission）：

- `moa-loop_*: allow` —— 循环状态工具放行，不弹权限确认
- `grep` / `glob` / `list: allow` —— 只读工具放行，避免 headless 轮次因权限询问挂起
- 每轮协议要求执行 agent「只允许 `moa_*` 与 `read`，任务外多想一步写进 note 回传」——bounded segment，防越界探索卡轮

### 任务书结构（todowrite）

每轮执行 agent 用**任务书结构**规划自己的活儿——循环不另造体系，直接用 opencode 原生 `todowrite`（交互会话里你看到的那套任务清单）。这是把 leader 的任务书纪律（改编自 khazix leader skill）带进无人值守轮次的方式：

- **任务清单 = todowrite，不是小作文**：开工先用 `todowrite` 把本轮任务拆成步骤，完成一步勾一步
- **验收 = 命令 + 机器可判的判定**，不是描述（如 `node --check` 过、冒烟脚本 exit 0、grep 数对）。步骤只在命令说 OK 时才算完成
- **反向验证（验真试验/变异测试）**：凡「坏了没人会知道」的检查，故意破坏一次实现重跑——必须变红；还原重跑必须全绿。检查失灵 = 验收全假。两次输出都贴进足迹.md 的验证节
- **红线·防作弊**：跳过、TODO 算完成、放松断言、mock、删测试、`|| true`、改阈值全部算失败；测试数只许 ≥ 基线
- **连败 3 次换任务**：同一条验收连败 3 次 → 标 blocked 换下一项（「没做成但说清了」合格，「做了但更糟」不合格）
- **断点恢复**：每轮开头先读 state.json + 足迹.md，先复述「做到哪了」再动手，禁止凭记忆续写

`.moa/` 下的模板已配套：界线.json（冻结验收 + 红线·防作弊 + mutationTest 验真试验）与足迹模板.md（含断点恢复节）。

## 三、状态协议（.moa/longloop/state.json）

```json
{
  "goal": "长程目标",
  "phase": "working | waiting_user | finished",
  "roadmap": [{ "id": "t1", "title": "...", "status": "open|in_progress|done|blocked", "note": "进度现场" }],
  "blockers": [{ "question": "要人决策的问题", "context": "...", "since": "ISO 时间" }],
  "finished": false
}
```

- `phase=waiting_user`：全部任务 blocked，等你答复——编辑 state.json 回复 blockers（改 question 为答复或删掉并恢复对应任务为 open），下轮自动恢复
- 机器字段（iteration/updated_at/last_round_change 等）由脚本维护，agent 不动
- 足迹.md 模板见 `.moa/longloop/足迹模板.md`；「弃选」区记录被放弃的路线，防未来重蹈

## 四、节奏与成本（经济模式默认）

- 默认 180 秒间隔；每轮一个 bounded 任务（flash 级为主），约 200-400 轮/天
- 无人值守约束写在每轮协议里：需求不清晰**不烧旗舰链**，标 blockers 等用户
- 想看开销：`opencode stats`

## 五、常见问题

| 现象 | 处理 |
|------|------|
| 连续 4 轮状态文件无变化自动停止 | 查 loop.log 与足迹.md；通常是任务全 blocked 或 agent 卡住，人工判断后重启（断点恢复） |
| 轮间隔太密/太疏 | -IntervalSec 调整；waiting_user 自动 1800s |
| 状态文件被外部改了 | 脚本每轮重读，立即生效；这就是「用户答复」通道 |
| 想换目标 | 停循环，改 state.json 的 goal + roadmap 重置（或删除 state.json 重新 -Goal 启动） |
| 机器重启 | 循环脚本断了就重启进程；state.json 在磁盘上，轮次从 1 重新计但进度不丢 |
| 桌面版看不到新会话 | 上游 bug（#31073）已知限制：手动点「加载更多」刷新列表；不影响循环运行 |
| 开了两个循环 | 不支持并发：一个 state.json 只能被一个循环驱动（会互踩状态），第二个请停掉，或用独立目录（-Dir）各跑各的 |
| Windows 下 `opencode run` 报 Access is denied | opencode.exe 被 Defender 误杀/拦（二进制被标记但 PE 正常）。修复：`npm install -g opencode-ai` 重装覆盖，或把 npm 全局目录加入 Defender 排除项 |
