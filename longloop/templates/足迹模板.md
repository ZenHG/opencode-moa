# 长程足迹（append-only）

> 每轮派发的执行 agent 完成后追加**一条**（由 moa_footprint_append 写入，格式如下）。
> 无进展的轮次也必须记录——把没做成的改名成成功视为作弊（loopx：no-progress ≠ success）。
> 证据用 ref（`commit:<sha>` / `smoke:<用例名>` / `pr:<编号>` / `run:<运行id>`），todo 完成/自述不算证据。

## 条目格式（每轮一条，锚定「做了什么/验证/证据/负结果/下一步」）

```
## <任务 ID> <标题>（<ISO 时间>）
- 做了什么：<关键动作，含文件路径>
- 验证：<命令 + 结果>（或「未验证」）
- 证据：<ref>（无则写：无 ref（todo 完成/自述不算证据））
- 结果：<done | blocked | partial>（partial 需在 state note 保留进度）
- 边界：<本轮改动边界，预期文件清单>（可选，P1-7 范围蔓延检测用；未声明写「未声明」）
- 负结果：<失败尝试/未达成的验收>（无则写「无」；无进展轮次必须写明原因）
- 下一步：<留给下一轮的问题或建议>（无则写「—」）
```

## 拦路虎分类（moa_blockers_add 可选参数，P1-8）

- `failure_type`：infra=基础设施 / code=代码缺陷 / permission=权限 / resource=资源 / deadlock=死锁 / unknown（默认）
- `wait_reason`：user=等用户答复（进 waiting_user）/ external=等外部 / resource=等资源 / internal=等内部（后三者不进 waiting_user，照常换任务）
- infra/deadlock 类：门童优先重试一次，重试仍败再标 blocked
